# 갱신

미리보기가 버퍼 변경·외부 변경·폭 변경을 반영해 다시 그리는 규칙이다. 화면 구조(fold·anchor·y 표·보류 spacer)는 [preview-view.md](preview-view.md) 가 설명한다.

## 변경 출처

- 변경 출처는 셋이다. `TextChangeListener.on_text_changed`(버퍼 단위이고, 어느 view 에서 고쳤든 변경마다 한 번 온다), `on_reload`, `on_revert` 다.
- `on_modified` 는 미리보기 갱신에 쓰지 않는다. 재로드 때 크기 0 인 중간 상태로도 오고, view 수만큼 온다.
- TextChangeListener 는 `is_applicable` 이 False 를 돌려주게 둔다(기본값이면 모든 버퍼에 자동으로 붙는다). 버퍼의 첫 미리보기 view 가 진입할 때 `attach` 하고, 마지막 미리보기 view 가 나갈 때 `detach` 한다.

## 편집

clone view 의 편집과 미리보기 중 다른 경로로 들어온 버퍼 변경이 여기에 해당한다.

- `on_text_changed` 안에서 바로 fold 를 다시 잡는다. 문서 끝에 붙은 글자와 fold 시작 앞에 넣은 글자는 fold 밖으로 드러나기 때문이다. 배치 B 는 `[1, size)` 를, 배치 A 는 anchor 가 있는 줄의 다음 줄부터 끝까지를 접는다. 줄 1 을 나누는 개행이 들어와 anchor 가 줄 2 로 밀렸을 때 새 줄 1 끝을 기준으로 접으면 모든 phantom 이 fold 안에 들어가 사라진다. phantom 은 그대로 보인다.
- `controller.EDIT_DEBOUNCE_MS` debounce 뒤 다시 파싱하고, 처음 달라진 블록부터 다시 추가한다. 줄 1 이 바뀌어 배치나 anchor 가 달라지면 버튼부터 전부 다시 추가한다.
- 보이지 않는 clone view 의 fold 도 편집 때 바로 다시 잡는다.

## 재로드

- Sublime Text 가 외부 변경을 감지해 파일을 재로드하면(창 활성화와 무관하다) fold 와 모든 phantom(도구줄 버튼 포함)이 지워져 원문이 그대로 드러난다.
- `on_reload` 안에서 바로 fold 를 다시 잡고, debounce 없이 파싱한 뒤 캐시된 html 을 다시 쓰면서 버튼 → 블록 순서로 처음부터 다시 추가한다.
- 재로드 표식을 `state` 에 남긴다. 복귀할 때 selection 복원 방식이 달라진다([preview-view.md](preview-view.md) §복귀).

## 다시 그리는 동안의 화면

`scroll_past_end` 가 false 이므로, 보류 위치 아래 한 화면이 그려지기 전에는 Sublime Text 가 viewport 를 그려진 내용 끝으로 잘라 내 문서 위쪽이 보인다. 이를 두 가지 방법으로 막는다.

- **빈 화면 보류**: 첫 조각에서 보류 위치를 적용하지 못하면 그 조각의 콜백에서(재로드는 `on_reload` 콜백에서) 보류 spacer 를 추가하고 viewport 를 그려진 내용 아래의 spacer 안에 둔다. 위치를 적용하는 콜백에서 viewport 를 정한 뒤 spacer 를 지운다. 화면은 빈 화면에서 바로 최종 위치로 바뀐다.
	- 보류는 세대가 바뀌어도 이어지고, 위치 적용·`scroll_to`(사용자 이동)·미리보기 종료로 끝난다.
	- 보류 중의 viewport y 는 위치가 아니므로 키보드 스크롤은 무시한다. Goto Symbol 은 보류 위치로 첫 선택을 정하고, 취소하면 보류를 이어 간다.
- **이중 버퍼**: 증분 갱신에서 처음 달라진 블록이 viewport 위에 있고 이전 그리기가 끝났으면, 옛 꼬리를 지우지 않고 새 꼬리를 그 아래에 추가한다. 새 블록의 y 는 잰 값에서 옛 꼬리 높이를 뺀 값이다. 보류 위치 아래 한 화면이 새 표로 그려진 콜백 하나에서 옛 꼬리를 지우고 표를 바꾼 뒤 viewport 를 정한다.
	- 그 전까지 위치 계산은 화면에 보이는 옛 표를 쓴다.
	- 새 세대가 오면 확정하지 않은 새 꼬리를 지운다.
	- 버튼이 바뀌는 세대에는 쓰지 않는다.

## 위치 유지

갱신 전 화면 맨 위 블록의 html 해시와 그 블록 안의 비례 오프셋을 기억했다가, 갱신 뒤 같은 해시의 블록을 옛 번호에서 가까운 순서로 찾아 복원한다. 같은 해시가 없으면 같은 번호의 블록으로 복원한다.

## 보이지 않는 미리보기

- 다시 그리기는 보이는 미리보기(창마다 각 그룹의 `active_view_in_group`)에만 바로 한다.
- 다른 탭·다른 창의 미리보기는 설정·테마 변경과 편집이 있을 때 다시 그릴 몫(전체 또는 갱신, 전체가 우선)만 표시해 두고, 활성화되거나 폴링이 보이는 view 로 감지할 때 다시 그린다. 활성화 때 폭이 바뀌었으면 폴링을 기다리지 않고 바로 다시 그린다.

## 폭과 글자 크기

- 뷰포트 폭 변경(창 크기, 사이드바, 분할)과 `font_size` 변경에는 이벤트가 없다. 보이는 미리보기·편집 view(창마다 각 그룹의 `active_view_in_group`)에 한해 `controller.POLL_MS` 간격으로 `viewport_extent()` 폭과 `font_size` 를 확인한다. 바뀌었으면 `controller.GEOM_DEBOUNCE_MS` debounce 뒤 미리보기는 전부 다시 렌더하고(글자 크기가 바뀌었으면 새 scheme 부터 만든다), 편집 모드 버튼은 다시 놓는다.
- 렌더가 시작되어 아직 view 의 폭·글자 크기를 읽지 않은 동안(파싱·scheme 인덱싱 대기)에는 폴링이 다시 렌더를 걸지 않는다. 그 렌더가 현재 값을 읽기 때문이다. debounce 가 끝날 때 값이 그려진 것과 같으면 다시 렌더하지 않는다.
- `on_load` 직후(새 창·세션 복구 직후) `viewport_extent()` 가 0 이면 폭이 생길 때까지 미리보기 진입을 미룬다.

## 파일 크기 상한

- 파일 크기가 `max_file_size` 를 넘으면 미리보기를 거부하고 상태바에 알린다.
- 블록 추가 비용은 블록 수에 비례하고 대부분이 Sublime Text 가 phantom 마다 `phantom_css` 를 다시 처리하는 비용이다. 블록 수가 수천에 이르면 블록 하나의 추가 비용도 처음보다 커진다. 기본 상한은 일반적인 문서 밀도에서 전체를 채우는 시간이 수 초 안에 들도록 정한 값이다. 그리는 일은 조각 단위라 그동안에도 UI 는 멈추지 않는다.
